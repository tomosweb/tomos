# Tomos 開発判断の基準

この文書は、Tomos の機能、画面、言葉遣い、配布方法を判断するときの基準です。

Tomos は、自分の言葉を Web に置きたい人が、安く、軽く、好きな見た目で、自分の Web を持てる選択肢になることを目指します。

ここでいう「持てる」とは、単に Web 上に公開できるという意味ではありません。自分の文章を Markdown ファイルとして扱い、自分で選んだ公開場所に置き、自分の判断と管理のもとで Web として維持できる、という意味です。

Tomos が優先するのは、無料であることそのものではありません。安く、軽く、理解しやすく、長く、自分の管理で続けられることです。

## 1. 対象にする人

Tomos が主に想定するのは、自分の言葉を Web に置きたい人です。

Web制作や開発の専門知識がない人でも、文章を書き、見た目を選び、自分のWebとして公開できることを重視します。

技術に詳しい人だけが使える道具にはしません。専門用語を知っている人にとって便利なことより、専門用語を知らない人が迷わず進めることを優先します。

## 2. 自分で持てること

Tomos は、文章を Markdown ファイルとして扱います。

Markdownファイルは、特定の管理画面やサービスの中だけに閉じ込められるものではありません。利用者が自分の手元で確認し、保管し、必要に応じて移動できる形式です。

Tomos は、利用者が自分で選んだ公開場所にファイルを置き、自分の判断でWebを維持できることを重視します。

## 3. 簡便に管理できること

Tomos は、自分で管理できることを大切にします。

ただし、自分で管理できることと、難しい操作を求めることは同じではありません。Tomos は、専門的な開発作業を前提にしすぎず、できるだけ簡便に公開、更新、保管できることを重視します。

設定項目を増やす場合は、その設定が本当に必要か、初めて使う人が意味を理解できるか、初期値のままでも困らないかを確認します。

## 4. 安く、軽く、長く続けられること

Tomos は、安く使えることを重視します。

ただし、無料であることだけを目的にしません。無料であっても、仕組みが複雑で理解しにくい場合や、特定の外部サービスに強く依存する場合は、Tomos の判断軸とは一致しません。

Tomos は、低コストで、軽く、壊れにくく、長く維持しやすい構成を優先します。

## 5. 好きな見た目を選べること

Tomos は、利用者が自分のWebの見た目を選べることを重視します。

ただし、見た目の自由度を高めるために、使い方が複雑になりすぎてはいけません。テーマは、専門知識がなくても選べる単位にします。

標準テーマは、文章を読みやすく公開できることを最優先にします。テーマ追加は、Tomos本体を複雑にしない範囲で行います。

## 6. 機能追加の判断

新しい機能を追加する場合は、次の観点で判断します。

- 自分の言葉をWebに置くことを助けるか
- 専門知識がない人にも理解できるか
- 初期設定や日常の更新を複雑にしないか
- ファイルとして持てることを妨げないか
- 特定の外部サービスへの依存を強めすぎないか
- 長期的な保守を重くしないか

便利であっても、Tomosの中心から外れる機能は追加しません。

## 7. 使う言葉の基準

Tomos では、利用者を見下すような言葉を使いません。

「素人」という言葉は、開発者同士の会話では意味が通じても、Tomos の文書では使いません。代わりに、「自分の言葉をWebに置きたい人」「Web制作や開発に詳しくない人」「専門知識がない人」といった表現を使います。

Tomos の文書では、専門用語を避けます。必要な専門用語を使う場合は、できるだけ短く説明します。

## 8. 優先しないこと

Tomos は、次のことを最優先にはしません。

- 高機能なCMSになること
- 開発者向けツールとして最適化すること
- 無料公開手段の代替になること
- すべての公開方法に対応すること
- 複雑なワークフローを標準にすること
- 最初から大規模サイトに対応すること

Tomos は、小さく始められ、理解できる範囲で続けられる Web の道具であることを優先します。

## 9. 判断に迷ったとき

判断に迷ったときは、次の問いに戻ります。

この変更は、自分の言葉をWebに置きたい人が、安く、軽く、好きな見た目で、自分のWebを持つことを助けるか。

この変更は、利用者が自分の文章とWebを、自分の判断と管理で続けることを助けるか。

この2つに明確に答えられない場合、その変更は急いで入れません。
