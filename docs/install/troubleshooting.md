# トラブルシューティング

## 画像投稿で送信容量の上限が表示される

Tomos Postの画像は1点10MBまでです。画像は1点ずつ送信するため、複数画像の合計容量は1回の送信上限に影響しません。

「現在の公開先で扱える容量を超えています」と表示される画像は、別の画像を選んでください。

## トップページは表示されるが、/about が Not Found

原因候補:

- `.htaccess` がアップロードされていない
- `.htaccess` が不可視ファイルとして漏れている
- サーバーで `mod_rewrite` が有効でない
- setupを開いたURLと、保存されたURL設定が一致していない

対応:

- Tomos設置ディレクトリ直下に `.htaccess` があるか確認する
- FTPソフトで不可視ファイル表示を有効にする
- `.htaccess` を再アップロードする
- setupを設置ディレクトリ直下の `setup/` から開き、保存された `site.url` と `base_path` が設置URLと一致しているか確認する
- サブディレクトリで動かない場合は `.htaccess` の `RewriteBase` を設置パスに合わせる

## setupで config.php が生成されない

原因候補:

- 設置ディレクトリにPHPから書き込みできない
- パーミッションが不足している
- `config.php.tmp` の作成または `rename()` に失敗している

対応:

- 一時的に設置ディレクトリを書き込み可能にする
- setup完了後に権限を戻す
- サーバーのファイルマネージャで `config.php` が生成されたか確認する

## 初回アクセスでトップページが表示されず setup/ に移動する

これは正常です。`config.php` がまだ生成されていない場合、Tomos はトップページを表示せず、現在のURLからの相対URL `setup/` へ移動します。

setup完了後に `config.php` が生成されると、トップページが通常表示されます。

## setupが「完了しています」と出てフォームが出ない

原因候補:

- `config.php` がすでに存在する
- `setup_completed` が `true`
- `setup_completed` が未定義の既存configとして安全側で無効化されている
- `security.disable_setup_after_install` が `true`

対応:

- 初回設置なら `config.php` を削除してから `/setup/` にアクセスする
- 再setupしたい場合は、`setup_completed => false` かつ `security.disable_setup_after_install => false` を明示する

## setupを無効化したのにPOSTが心配

Tomosは、setup無効時にCSRF検証や `config.php` 生成処理へ進まない設計です。

それでも公開環境では、setup完了後に `setup/` ディレクトリを削除またはリネームしてください。

## cache/index/pages.json が見えてしまう

原因候補:

- `.htaccess` がアップロードされていない
- `cache/.htaccess` または `cache/index/.htaccess` がアップロードされていない
- サーバーで `.htaccess` が無効

対応:

- `cache/.htaccess` と `cache/index/.htaccess` があるか確認する
- `.htaccess` が使えるホストか確認する
- `.htaccess` が使えない場合は、サーバー設定で `cache/` への直接アクセスを拒否する

## content内にフォルダを作ったら表示が崩れる

Tomosでは、`content/` 配下にフォルダを作れます。

```text
content/
  diary/
    2026-07-10.md
  2026/
    07/
      sample.md
  notes/
    memo.md
```

空フォルダや画像ファイル、`.DS_Store` などはページとして扱われません。ページとして扱われるのは `.md` ファイルです。`2026/` や `1/` のような数字だけのフォルダ名も、ページ番号やIDではなく通常のフォルダ名として扱います。

フォルダ内のMarkdownが表示されない場合は、ファイル名の拡張子が `.md` になっているか、`content/` の外を参照するようなパスになっていないか確認してください。

日本語、`【】`、`（）`、半角括弧、空白を含むMarkdownファイル名も扱えます。Tomos Postで投稿する場合、`/` や `\` などパスとして危険な文字は安全な名前へ変更されます。

Obsidian形式の `[[ページ名]]` リンクは、インデックス生成時に作られる `cache/index/link-aliases.json` を使って解決します。ファイルを追加・削除・リネームした後にWikiリンクが古い場合は、`cache/index/pages.json` を削除してインデックスを再生成してください。インデックス再生成時には、古い本文HTMLキャッシュも再生成対象になります。

通常表示を軽くするため、Tomosはページ表示のたびに `content/` 全体を走査しません。FTPでMarkdownを追加したあとに一覧、検索、タグ、Wikiリンクが古い場合は、キャッシュ再生成が必要になることがあります。

同じ名前のファイルが複数ある場合、`[[読書メモ]]` のようなbasenameだけのリンクは未解決扱いになります。`[[2026/読書メモ]]` のようにフォルダ名を含めて指定してください。

## ページを更新したのに表示が変わらない

原因候補:

- `cache/html/` に古いHTMLキャッシュが残っている
- Markdownファイルの更新日時が変わっていない

対応:

- `cache/html/` 内の `.html` と `.json` を削除する
- Markdownファイルを保存し直し、更新日時が変わることを確認する
- 次回アクセス時にHTMLキャッシュが再生成されることを確認する

## Markdownの表や太字が反映されない

原因候補:

- 古い本文HTMLキャッシュが残っている
- Markdownの表の区切り行が不足している

対応:

- 表は `|---|---|---|` のような区切り行を入れる
- 表示が古い場合は `cache/html/` 内の `.html` と `.json` を削除する
- Tomosは基本Markdown記法とGFM形式のテーブルに対応しています

## cache/html/ に書き込めない

原因候補:

- `cache/html/` が存在しない
- `cache/html/` のパーミッションが不足している
- サーバーのPHP実行ユーザーに書き込み権限がない

対応:

- `cache/html/` と `cache/html/.htaccess` があるか確認する
- `cache/html/` の書き込み権限を確認する
- 書き込めない場合でもページ表示自体は継続されます

## cache/html/ がHTTPで見えてしまう

原因候補:

- `cache/html/.htaccess` がアップロードされていない
- サーバーで `.htaccess` が無効

対応:

- `cache/html/.htaccess` があるか確認する
- `.htaccess` が使えない場合は、サーバー設定で `cache/html/` への直接アクセスを拒否する

## CSSや画像が読み込まれない

原因候補:

- `public_base_path` が間違っている
- テーマアセットがアップロードされていない
- `themes/tomos-minimal/assets/` が欠けている

対応:

- 通常ホストでは `public_base_path` を空にする
- 特殊なプロキシ構成では `public_base_path` にブラウザへ出力したいURLパスを入れる
- `base_path` や `public_base_path` にサーバー内の実パスを入れない
- `themes/tomos-minimal/assets/style.css`、`favicon.png`、`ogp.png` があるか確認する

## テーマがsetup画面に表示されない

原因候補:

- テーマディレクトリが `themes/` 配下にない
- `theme.json` がない
- `theme.json` が正しいJSONではない
- `theme.json` の `name` がディレクトリ名と一致していない

対応:

- テーマを `themes/テーマ名/` に置く
- `theme.json` の `name` とディレクトリ名を揃える
- 標準テーマ `themes/tomos-minimal/` が含まれているか確認する

## テーマが選択できない

原因候補:

- 必須テンプレートが不足している
- `assets/style.css` がない
- テーマ内にPHPファイルが含まれている
- テンプレート内に `<?php`、`javascript:`、`data:text/html` などの危険な記述がある

対応:

- `templates/layout.html`、`templates/page.html`、`templates/list.html` を確認する
- `assets/style.css` を確認する
- `.php`, `.phtml`, `.phar`, `.php5`, `.php7` をテーマ内から取り除く
- setup画面に表示される無効理由を確認する

## テーマ変更後に表示が崩れる

原因候補:

- テーマのCSSやテンプレートが不足している
- テーマが想定するクラスと本文HTMLが合っていない
- HTMLキャッシュの本文HTMLが古い

対応:

- テーマ検証で警告やエラーが出ていないか確認する
- 必要に応じて `cache/html/` 内の `.html` と `.json` を削除する
- 通常はレイアウトHTML全体はキャッシュされないため、テーマ変更後のレイアウトは新テーマで表示されます

## /post/theme/ が開かない

原因候補:

- `/post/` で管理用合言葉を入力していない
- `post/theme/` ディレクトリがアップロードされていない
- Tomos Postが無効になっている

対応:

- 先に `/post/` を開き、サイト設定からテーマ切り替えへ進む
- `post/theme/` ディレクトリが配布物からアップロードされているか確認する
- setupまたは `config.php` でTomos Postが有効か確認する

## /post/theme/ でテーマを保存できない

原因候補:

- CSRFトークンの有効期限が切れている
- 選択したテーマが無効
- `config.php` にPHPから書き込みできない

対応:
- `/post/theme/` を開き直して、もう一度テーマを選ぶ
- 無効テーマの理由を確認する
- `config.php` にPHPから書き込めるか確認する

- 画面を再読み込みしてからもう一度保存する
- 無効テーマの理由を確認する
- `config.php` の書き込み権限を確認する

## RSSやOGPのURLが相対URLになる

原因候補:

- `site.url` が正しくない
- setupを設置ディレクトリ以外のURLから開いた、または既存 `config.php` のURL設定が古い

対応:

- 新規setupでは、設置ディレクトリの `setup/` を開き直してURLを自動取得させる
- 既存環境では `config.php` の `site.url` と `base_path` を確認する

## Tomos Postで投稿できない

原因候補:

- Tomos Writeで保存したファイルを選んでいない
- 管理用合言葉が違っている
- CSRFトークンの有効期限が切れている
- `.md` / `.markdown` / `.txt` 以外のファイルを選んでいる
- 保存先フォルダやファイル名に危険なパス指定が含まれている
- 同じ名前のファイルがすでにある
- ファイルサイズが1MBを超えている
- 短時間に投稿試行が続いたため、一時的に制限されている

対応:

- Tomos Writeで `.md` として保存したファイルを選ぶ
- 画面を再読み込みしてからもう一度投稿する
- setup完了時に控えた管理用合言葉を確認する
- Markdown内の `folder` が自動反映された場合も、Tomos Post画面の保存先フォルダ欄を確認する
- 保存先フォルダに `../`、先頭 `/`、URL、制御文字など危険なパス指定を入れない
- ファイル名に危険な文字が含まれる場合、Tomos Postでは安全な名前へ変更されるため、投稿結果画面の保存先を確認する
- 同名ファイルがある場合は別のファイル名にする
- 短時間に何度も投稿を試した場合は、しばらく時間をおいてから再度試す

## Tomos Postで投稿を取り下げられない

原因候補:

- 公開URLがTomosの設置URL外になっている
- `/post/`、`/setup/`、`/search/` などの予約パスを指定している
- content内パスが `.md` ではない
- 管理用合言葉が違っている
- CSRFトークンの有効期限が切れている
- 短時間に投稿や取り下げを繰り返したため、一時的に制限されている

対応:

- Tomos内の公開URL、または `diary/2026-07-07.md` のようなcontent内パスを指定する
- 画面に表示された確認結果と別タブ確認リンクで対象ページを確認する
- 画面を再読み込みしてからもう一度試す
- 短時間に何度も試した場合は、しばらく時間をおいてから再度試す

## trashを空にできない

原因候補:

- 管理用合言葉が違っている
- 確認欄に `完全削除` と入力していない
- 短時間に操作を繰り返したため、一時的に制限されている
- サーバーの権限により `trash/` 内のファイルを削除できない

対応:

- 管理用合言葉を確認する
- 確認欄に `完全削除` と正確に入力する
- しばらく時間をおいてから再度試す
- サーバーのファイルマネージャで `trash/` の権限を確認する

## Tomos Postの合言葉を忘れた

既存の合言葉は画面で確認できません。復元ではなく、新しい合言葉を再発行します。

手順:

1. 設置ディレクトリ直下に `post-reset.enable` という空ファイルを置く
2. `/post/reset/` にアクセスする
3. 新しい合言葉を作成する
4. 表示された合言葉を安全な場所に控える
5. `post-reset.enable` を削除する

再発行後、古い合言葉は使えなくなります。
