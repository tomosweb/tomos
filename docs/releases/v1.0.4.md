# Tomos v1.0.4

Tomos v1.0.4は、Tomos PostとTomos Writeの往復編集を安定させるとともに、Tomosの記事をBlueskyへ告知できるSocial Publishingを追加する互換更新です。

## Included scope

### Social Publishing / Bluesky

- Frontmatterの `social` / `social_text` 指定に応じて、Tomos記事公開後にBlueskyへ告知できます。
- Tomos記事の公開とBluesky投稿は分離され、Bluesky側の失敗で記事公開をrollbackしません。
- Bluesky OAuth接続、投稿文の自動生成/手動指定、external card、投稿履歴、二重投稿防止に対応します。
- Tomos Publisherは送信ごとの `request_id` で公開結果を取得し、Tomos公開・Bluesky投稿・再投稿防止・下書きをObsidian Noticeへ表示します。
- Publisherから作成した記事は安全な管理記録に基づいて再送更新でき、Publisher管理外の既存記事は自動上書きしません。
- Bluesky連携設定画面をTomos Post共通UIへ統一しました。
- Markdownを `content/` へ直接配置した場合の自動Social Publishingはv1.0.4では対象外です。

### Tomos Write / handoff

- Tomos Writeとのhandoffでready probe、bounded retry、ACK、transaction ID、重複抑止を行います。
- Tomos WriteからのMarkdownを内部import入口へ直接渡し、Tomos Postの1 MiB Markdown契約を維持します。
- direct handoffのeditable updateでは、既存管理画像を再アップロード不要として扱います。
- Markdownから削除された管理画像は、他の記事やdraftから参照されていないこととImageReferenceIndexの安全条件を確認した後にcleanupします。
- conflict、Markdown更新失敗、index warning、source記事を残す保存では、既存画像を削除しません。
- Tomos Writeのcanonical endpoint、exact origin/session/source validation、HTTPS境界、COOP互換を維持します。
- v1.0.3で導入したTheme asset cacheとfavicon hotfixを維持します。

## Compatibility

- v1.0.3からv1.0.4へ、署名付きTomos Updateで更新します。
- `config.php`、`content/`、uploads、サイト固有Theme、cache/storage/trashの運用データはCore Updateの更新対象に含めません。
- Tomos Write v0.4.0と組み合わせて、公開済み記事の編集・画像表示・更新を行えます。旧Tomos Writeとの基本Markdown handoff互換も維持します。
