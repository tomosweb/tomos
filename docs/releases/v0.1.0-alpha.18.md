# Tomos v0.1.0-alpha.18

## 重要：v0.1.0-alpha.17から更新する方へ

v0.1.0-alpha.18への更新は、次の2段階です。

1. Tomos Updateで `tomos-update-0.1.0-alpha.18.zip` を適用します。
2. 更新後に `/post/update-finalize/` を開き、「Updater更新を反映する」を実行します。

**2まで完了して、v0.1.0-alpha.18への更新は完了です。**

1の完了後はVERSIONが `0.1.0-alpha.18` と表示されますが、`update/index.php` と `core/UpdateService.php` はまだ反映待ちです。2を完了するとalpha.18の新しいUpdaterへ完全に移行し、以降の公式オンライン更新機能を利用できます。

## 追加

- Tomos Updateから公式の更新情報を確認し、ブラウザ上で次の1バージョンの更新内容を取得・確認できるようにしました。
- オンライン更新と従来の手動Update ZIP更新を、同じ署名検証・確認・適用・バックアップ・rollback経路へ統合しました。

## 改善

- Update ZIP manifestに正確な更新元を示す `from_version` を追加し、現在のTomos VERSIONと一致する場合だけ更新できるようにしました。
- オンライン更新、手動Update ZIP更新のどちらでも段階を飛ばした更新を拒否します。
- 更新確認画面で `現在バージョン → 更新先バージョン` を明示します。
- オンライン更新情報やUpdate ZIPを取得できない場合でも、手動Update ZIP更新を引き続き利用できます。

## 配布・互換性

- v0.1.0-alpha.17から本リリースへのUpdate ZIPは、新manifest仕様へ移行するための1回限りのlegacy bridgeです。
- legacy bridgeでは `from_version` と `minimum_version` に同じ `0.1.0-alpha.17` を記録し、alpha.17の旧Updaterとalpha.18以降の新Updaterの双方で検証できます。
- alpha.18以降の通常Update ZIPは `from_version` のみを使用します。
- 手動の署名済みUpdate ZIP更新は、alpha.18以降も正式な更新経路として利用できます。

## 安全性

- 公式catalogは次の更新先を案内するために使用し、更新の真正性は従来どおり署名済みmanifestで確認します。
- 公式Update ZIP取得時はHTTPS、公式host、redirect、容量、SHA-256を検証します。
- `config.php`、記事、画像、runtime data、credentialはUpdate対象に含めません。
- 自動更新、連続多段更新は行いません。各更新は利用者の確認操作を必要とします。
