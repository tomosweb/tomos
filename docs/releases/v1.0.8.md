# Tomos v1.0.8

## Summary

BlueskyのOGP画像付き投稿を安定化するパッチリリースです。

Tomos Postでは記事保存を先に完了し、BlueskyへのSocial Publishingを新しいリクエストで再開する構造へ変更しました。あわせて、Blueskyカード用JPEGのEXIF Orientation補正とGD画像処理のメモリ保護を追加します。

## Changes

- 記事保存とBluesky投稿を別リクエストへ分離し、Bluesky側の画像処理が重い場合でも記事公開を先に確定します。
- 保存済みMarkdownからFront Matterの `image:` を再解決し、保存済み記事OGP画像をBluesky external cardへ使用します。
- ローカルOGP JPEGのEXIF Orientation 2〜8を画素へ反映してからBlueskyへ送信します。
- 外部URLから取得したJPEGについてもEXIF Orientation 2〜8を補正します。
- 1.8MB未満のJPEGでもOrientation補正が必要な場合はraw bytesをそのまま送信しません。
- 大きなJPEGはOrientation補正後に長辺1600px以下へ縮小し、Blueskyの画像上限に収まるよう再圧縮します。
- GD展開前に必要メモリを見積もり、安全に処理できない場合は画像なしカードへフォールバックします。
- Social Publishingが失敗しても、保存済み記事とMarkdownは削除・rollbackしません。
- deferred Social Publishing、Front Matter OGP画像、Orientation 2〜8、PNG/WebP、大容量JPEG、メモリガードの回帰テストを追加しました。

## Update transition

v1.0.7からv1.0.8へのBrowser Updateを対象とします。

## Compatibility

- 記事、画像、設定、追加Themeなどの利用者データは更新対象に含めません。
- Bluesky external cardのBlob upload → external.thumbの公式フローを維持します。
- 記事本文用画像とBlueskyカード用の派生画像は分離し、元の記事画像を変更しません。
- Bluesky画像処理が失敗した場合も記事公開を維持します。
