# Tomos v1.0.6

Tomos v1.0.6は、Blueskyの外部リンクカードで記事のOGP画像を表示できるようにし、Tomos WorkspaceからInbox APIへブラウザ経由で接続するためのCORS基盤を正式収録する互換更新です。

## Included scope

### Bluesky OGP image cards

- 公開記事に `og:image` がある場合、Blueskyのexternal cardへ画像を表示します。
- OGP画像はBlueskyへBlobとしてアップロードし、`app.bsky.embed.external.external.thumb`へ設定します。
- OGP画像がない場合、画像取得に失敗した場合、またはBlob uploadに失敗した場合は、従来の画像なしexternal cardへ安全にフォールバックします。
- Social Publishingの失敗によってTomos記事公開をrollbackしない既存設計を維持します。
- Front Matterの `image:` にTomos管理画像を指定した場合も、Publisher Inbox受信、画像参照index、cleanupの管理対象として扱います。

### Bluesky OAuth compatibility

- 画像Blobアップロードのため、Bluesky OAuth scopeへ `blob:*/*` を追加します。
- 既存のBluesky接続は従来のテキストカード投稿を継続できます。
- 画像付きカードを利用する場合は、v1.0.6へ更新後にBlueskyを一度再接続し、新しいBlob権限を取得してください。

### Tomos Workspace / Inbox API

- 許可したブラウザOriginから `/post/inbox/api/` を利用できるCORS対応を正式収録します。
- `OPTIONS` preflightをtoken認証より先に処理し、許可Originには `204` を返します。
- Workspaceが利用するGET / POST / chunked image upload用ヘッダーを許可します。
- 未許可Originは拒否し、従来のTomos Publisher token認証は維持します。
- `core/InboxApiCors.php` をrequired source / distribution / installed runtimeへ固定します。

## Compatibility

- v1.0.5からv1.0.6へ、署名付きTomos Updateで更新します。
- `config.php`、`content/`、uploads、サイト固有Theme、cache/storage/trashの運用データはCore Updateの更新対象に含めません。
- Tomos Write、Tomos Publisher、既存Social Publishingの互換を維持します。

## Verification

- PHP lint、Distribution build、全Core regression checksをローカルで実行します。
- v1.0.5公開artifactをbaselineとしてv1.0.5 → v1.0.6 Update packageを生成・検証します。
- Installer Phase 1〜5、署名、checksum、Browser UpdateをActions-independent Local Release Gateで確認します。
- 公開HTTPS環境でBluesky再接続、OGP画像付き実投稿、画像なしfallbackを確認します。
- Workspace許可OriginからのOPTIONS preflightが204となり、未許可Originが拒否されることを実サーバーで確認します。
