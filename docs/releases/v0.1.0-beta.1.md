# Tomos v0.1.0-beta.1

## 概要

v0.1.0-beta.1は、alpha期間で実装したTomosの主要機能・投稿・更新・インストール経路を、一般利用を想定した安定運用段階へ移す最初のbeta版です。

新機能を増やすことより、alpha最終版のシステム整合性監査と回帰テスト強化を反映し、失敗時のrollback、複数ファイルの世代整合、同時更新、Update経路の一貫性を確認した状態をbetaの基準としています。

## 主な変更

### 信頼性・整合性

- Markdownと管理画像を一つの公開transactionとして扱い、途中失敗時のrollbackを強化しました。
- `pages.json` と `link-aliases.json` の世代不一致を検出し、不整合な索引を利用しないようにしました。
- HTML cacheのHTMLとmetaが異なる世代の場合にcacheを利用しないようにしました。
- `config.php` の同時更新をlockとcompare-and-swapで保護し、silent lost-updateを防止しました。
- Passkey credentialの利用回数更新を直列化し、`sign_count` と利用時刻が後退しないようにしました。
- Update / updater self-update / Theme / Postのfailure injectionを追加し、途中失敗とrollback失敗を回帰確認できるようにしました。
- derived indexとcacheの一時ファイルをrandomized same-directory temporary fileへ整理しました。

### Tomos Postの画像投稿

- GDが利用できない場合、画像加工用メモリの安全判定を満たさない場合、または画像加工中に例外が発生した場合も、安全側へフォールバックして元画像を保存します。
- 元画像保存が成功した場合、これらの内部的なフォールバック理由を利用者向けの注意表示には出さないようにしました。
- EXIF向き補正不可など利用者に意味のある警告と、画像保存自体の失敗エラーは従来どおり維持します。
- 画像容量上限、長辺2048px、GDメモリ安全判定、JPEG/WebP品質、PNG圧縮は変更していません。

## アップデート

v0.1.0-alpha.19からv0.1.0-beta.1へは、Tomos Post → Tomos Updateの通常更新、または署名済みUpdate ZIPを使用します。

```text
product: Tomos
from_version: 0.1.0-alpha.19
version: 0.1.0-beta.1
```

`from_version`は現在の`VERSION`と完全一致する必要があります。自動多段更新は行いません。

alpha.17から更新する場合は、alpha.18のUpdater移行を完了し、alpha.19を経由してbeta.1へ1versionずつ更新してください。

## データ保持

Tomos Updateは、利用者の`config.php`、`content/`、運用データ、登録済みPasskey credential、利用者が追加したテーマを通常Update対象にしません。更新前のバックアップは引き続き推奨します。

## beta版について

beta.1は正式リリース版ではありません。既知不具合の修正、互換性・安全性・運用性の改善を優先し、大きな新機能追加は原則としてbeta.1のリリース境界へ持ち込みません。
