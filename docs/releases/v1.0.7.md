# Tomos v1.0.7

## Summary

Tomos Postで、記事Front Matterに指定したローカルOGP画像を投稿時にTomos管理画像へ変換し、記事単位のOGP画像として正しく利用できるようにします。

## Changes

- Front Matterの `image:` にローカル相対画像を指定した場合、Tomos Postで元画像を選択して投稿できます。
- 投稿時のみ `image: image/example.jpg` のようなローカル参照を `image: images/tms-....jpg` へ変換します。
- Tomos PostではFront MatterのOGP画像と本文画像を別々に検出・確認し、それぞれ独立してTomos管理画像へ変換します。
- Obsidianの `![[image.jpg]]` を含む本文画像も本文画像として扱い、Front Matterの `image:` と混同しません。
- BlueskyへOGP付きで投稿する場合は、Tomosが保存した記事OGP画像を `com.atproto.repo.uploadBlob` へ渡し、返却Blobをexternal cardの `thumb` に設定します。
- Blueskyの画像上限に合わせ、カード用画像が大きい場合は記事画像そのものを変更せず、Bluesky送信用だけ縮小・再圧縮して2MB未満に収めます。
- 元のローカルMarkdownファイル自体は変更しません。
- 記事Front Matterに有効な `image:` がある場合は、その記事画像をOGP画像として優先します。
- 記事Front Matterに `image:` がない場合は、公開サイトに設定されている既定OGP画像を利用する従来仕様を維持します。
- 外部HTTP/HTTPS画像、サイトルート相対画像、既存のTomos管理画像参照は従来どおり扱います。

## Update transition

v1.0.6からv1.0.7へのBrowser Updateを対象とします。

## Compatibility

- 記事、画像、設定、追加Themeなどの利用者データは更新対象に含めません。
- Bluesky external cardは公式のBlob upload → external.thumbの流れを使用します。
- 記事本文用画像とBlueskyカード用の縮小画像は分離し、記事画像の品質・保存内容は変更しません。
- Tomos Publisher 0.2.6は公開せず、Tomos v1.0.7確認後にPublisher 0.3.0をリリース予定です。
